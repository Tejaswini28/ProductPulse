# Product Pulse — Streamlit demo

A light, evidence-first workspace for Product Managers. **AI investigates. PM decides.**

## Run

From Product Pulse, use the existing Python 3.12 environment:

```bash
source .venv/bin/activate
python -m pip install -r requirements-app.txt
python -m streamlit run app.py
```

Open http://localhost:8501. Investigations require valid OPENAI_API_KEY and PINECONE_API_KEY values in .env, plus the current documents already indexed by notebook sections 2–6. Knowledge comparisons use the same credentials; Health scans require OpenAI only. Charts and source viewers read local synthetic data without API calls.

## What works

- Product/day filtering, complaint charts, historical health cards, API mapping and source evidence.
- Issue-to-investigation handoff, complaint/customer/date/time inputs, session reconstruction, evidence panels, PM review and investigation history.
- Semantic documentation comparisons with complete-document coverage and validated quotes. Confirmation gates drafting; wording approval gates export and is invalidated by edits.
- Deduplicated response-code patterns across investigations, with opportunity exploration notes.

## Analysis scope

Investigate now runs the shared LangChain Investigation Agent with GPT-4.1 mini, the seven read-only tools and Pinecone RAG. Run Health Scan and Check Knowledge Consistency now run their own GPT-4.1 mini agents. Historical charts and separately labeled threshold signals remain Python calculations. All evidence panels show records actually returned to the agent; missing panels do not imply missing source data. API errors or invalid citations produce an incomplete run, never a fallback rule-based finding.

Historical service flags require same-product/day corroboration: ≥5 percentage-point product metric decline, ≥3-point API error-rate increase, and ≥3 complaint records. Experience flags require ≥3 complaints and ≥3 sessions with unavailable-date responses. These are demo thresholds, not statistically validated alerts. Daily metrics and incident records do not prove exact overlap with a customer's attempt. Missing API telemetry is shown explicitly.

The Knowledge Agent compares meaning across all four documents and may use Pinecone for focused follow-up. A completion validator requires all four documents to have been read, actual quotations, and references to the designated authority and downstream source. Missing-information claims remain scoped observations for PM review. Draft wording is generated by GPT-4.1 mini only after the PM confirms a gap; wording approval is separately required for export.

## Extend

- `pulse/data.py`: CSV loading, source references and filters.
- `pulse/analysis.py`: health rules, evidence investigation and deduplicated patterns.
- `pulse/docs.py`: documentation service and review-gated drafts. The local documentation service supports an injected retriever; AI investigations use `pulse/rag.py` directly.
- `pulse/ui.py`: reusable cards, evidence expanders and styling.
- `pulse/agent.py`: shared bounded loop, citation registry and reserved final-report turns.
- `pulse/health_agent.py`: Python operational summaries, autonomous health review and per-product report validation.
- `pulse/knowledge_agent.py`: full-document comparison, quote/coverage validation and confirmed-gap AI drafting.
- `pulse/agent_tools.py`: per-run tool instances.
- `pulse/rag.py`: existing Pinecone connection and deterministic namespace calculation; 512 dimensions match the current notebook.
- `pulse/investigation_service.py`: live-agent entry point and conversion of returned evidence for UI panels.
- `app.py`: Streamlit navigation and session-local review interactions.

Review state lives in the browser's Streamlit session, not a database. A reload/new session can lose it. Source-file changes invalidate prior session approvals. Export is local download only; no publishing, messaging or commitments exist.

## Agent triggers and limits

An issue card's Investigate button starts the agent directly. Submitting a complaint or selecting Investigate Further starts a new run. The latter includes PM notes. Other reruns and review clicks do not call the model. Inside a run, the model autonomously selects tools; at most 10 evidence-tool calls and 12 model calls are allowed (SDK retries may add requests). Every completed report awaits PM review. Unattended scheduling is not enabled.

Use notebook section 30 to run exactly the same service. The original sections 21–28 explain the agent mechanics; sections 24–25 now delegate to the shared implementation. Section 29 retains local analysis examples for comparison.

Keys are reread on each explicit run. The app performs no automatic index writes. If the current namespace is absent or dimensions differ, rerun the notebook ingestion with matching configuration. Never paste keys into source files or share .env.

## New agent actions

- **Run Health Scan:** uses OpenAI with operational CSV tools; no Pinecone needed. Reports remain tied to selected products/dates and do not rerun on navigation.
- **Check Knowledge Consistency:** uses OpenAI, full local document reads and optional Pinecone retrieval. New comparisons reset approvals; changing source data invalidates previous run state.
- **Draft Update:** separate model call after PM confirmation only. Export remains disabled until the exact preview is approved.

Notebook sections 31–33 expose the same tools/services step by step. The default drafting example is disabled until the PM deliberately confirms a gap. Agents do not run unattended on a schedule. Their internal tool selection is autonomous after an explicit trigger.
